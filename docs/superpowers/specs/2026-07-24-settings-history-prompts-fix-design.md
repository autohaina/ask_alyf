# Ask ALYF 设置保存、测试历史与快捷提示修复设计

日期：2026-07-24

状态：用户已要求继续修复

## 设置保存

移除误加到 `Ask ALYF Settings` 的测试字段 `111`。该字段把普通设置页纳入海纳多币种字段校验，数字字段名触发验证异常。迁移后清除对应数据库 DocField/伴生元数据和缓存，并确认 DocType 仍为不可提交的 Single DocType。

附件中的 `content_main.js` 来自浏览器扩展内容脚本，不是 Frappe/Ask ALYF 资源。其键盘事件异常可能干扰快捷键，但服务端保存失败的直接原因是非法字段 `111`。页面应使用“保存”而不是“提交”；清元数据后复核实际按钮和请求动作。

## 测试历史

`Test Conversation` 与 `Tool Error Test` 由自动化测试插入但未清理。测试改为登记所创建会话，并在 `tearDown` 中精确删除。现有 22 条污染记录先导出名称、标题、创建时间和所有者，再按精确标题及已确认的测试时间批次删除。

## 随机快捷提示

启动数据写入 `frappe.boot.ask_alyf` 后必须主动清空提示缓存；点击“新聊天”也必须在应用会话前清空，即使服务端复用了同一个空会话名称。这样首次异步启动和重复新聊天都会重新按当前角色随机选择提示。

## 验证

- Ask ALYF Settings 单元/集成测试通过，源 JSON 不再包含 `111`。
- 会话测试运行前后不会残留新增的测试标题记录。
- Node 测试覆盖启动数据到达和同名新会话时的缓存失效。
- 构建、迁移、清缓存和重启后，在 `hn.haina.cn` 验证设置页保存和新聊天快捷提示。
